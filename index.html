How a draw is derived
preimageinput·draw·drawn·ckd → hashsha256 → u256 → reducemod numbers left → 7
ckd
The round's key exchange, all of it public and all of it hashed: pk1, pk2, an ElGamal app key the casino draws at random for the round alone (s·G1, s·G2, the scalar thrown away); big_y, the MPC network's ephemeral key; and big_c, its derived key for (contract, path) encrypted to pk1. Nobody can open it, and nobody needs to: e(pk1, G2) = e(G1, pk2) and e(big_c, G2) = e(H(mpk ‖ app_id), mpk) · e(big_y, pk2) hold for the exchange. The MPC contract checks both before answering; Verify checks them again. One per round.
path
round-N for game 0, game-G-round-N otherwise.
input
The round's public data from get_roll_input: game, round, limits, pot, every bet.
draw, drawn
This draw's index and the numbers already out — what gives each number a preimage of its own.
reduce
Over the numbers still in the drum, so a repeat is reconsidered rather than drawn twice. One number decides a single-outcome game; bingo draws until a card fills.
✓
Set by Verify. Green: the key exchange passed both pairing checks against the MPC network's public key and every number of the round recomputed from the contract's own inputs. Amber: the numbers recomputed but the pairing library did not load.
