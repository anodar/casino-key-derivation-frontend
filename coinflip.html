How a draw is derived
preimageinput·draw·drawn·ckd → hashsha256 → u256 → reducemod numbers left → 7
ckd
The round's key exchange with the MPC network, all of it public and all of it hashed: pk1, pk2, the ElGamal app key the casino draws at random for the round alone; big_y, big_c, the network's answer — its derived key for (contract, path) encrypted to that app key, so e(big_c, G2) = e(H(mpk ‖ app_id), mpk) · e(big_y, pk2); sk, the app key's secret, published once the round has drawn; and key = big_c − sk·big_y, the derived key opened with it: the randomness itself. One exchange per round.
path
round-N for game 0, game-G-round-N otherwise.
input
The round's public data from get_roll_input: game, round, limits, pot, every bet.
draw, drawn
This draw's index and the numbers already out — what gives each number a preimage of its own.
reduce
Over the numbers still in the drum, so a repeat is reconsidered rather than drawn twice. One number decides a single-outcome game; bingo draws until a card fills.
✓
Set by Verify, four checks per round: big_c pairing-checks against the MPC network's public key as the derived key for the round's path; sk is the scalar behind pk1, pk2 and opens big_c to key; every number recomputes from the preimage above; and the casino's receipts to the MPC contract, counted off the indexer, ask for the round's path exactly once. Green: all four hold. Amber: none fails, but the pairing library did not load or the indexer could not be reached. Red: one fails. Hover a seal for the verdicts.
